## Invariants to preserve while repairing functionality

`JobApplicationWorkflowService.getAuthoritativeApplicationPackage` (`:2834`) returns server-stored content; ticket issuance (`:2925`) binds identity and package version/hash; submission (`:3050-3226`) verifies approved content and creates a fresh frozen adapter payload. `claimApplicationExecution` / `startApplicationExecution` (`:3236-3270`) commit durable at-most-once state before the adapter boundary. A timeout/crash becomes UNKNOWN and prevents replay. Real submitted state requires `adapterResult.status==='SUBMITTED'`, no blocked final submit, and `authorizedSubmissionExecuted===true` (`:3301`). Built-in adapters return HANDOFF_READY instead.

Repairs must fix DTOs and UI wiring around these guards, not delete them. Application/package staging, successful durable execution of a handoff, valid artifacts or a user clicking the platform's Submit control must never become proof of employer submission. No approval weakening is needed to correct obsolete legacy assertions.
